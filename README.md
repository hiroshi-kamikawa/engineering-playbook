# Engineering Playbook

個人のエンジニアリング環境を、ゼロから一貫して再構築するためのルール・手順・探求記録。

このリポジトリは dotfiles の寄せ集めではない。設計判断、AI エージェントの使い方、開発フロー、検証基準を記録し、プロジェクトが変わっても再利用できる個人の運用基盤である。

## まず読む

- [Codex Engineering Playbook](docs/codex-engineering-playbook.md) — Codex、Skills、モデル、セッションの実践ガイド
- [リポジトリの構成と記録方針](docs/repository-structure.md) — どこに何を書くか

## 使い方

1. 新しいプロジェクトを始める前に、Playbook の「開始時フロー」を確認する。
2. 実際に役に立った手順・判断・失敗を、該当するディレクトリに短く追記する。
3. 重要で再検討コストが高い判断は `decisions/` に ADR として残す。
4. 定期的に、古くなったセットアップ手順とリンクを検証する。

## ディレクトリ

```text
setup/       再現可能な開発環境のセットアップ手順・スクリプト
principles/  設計・品質・安全性に関する判断原則
workflows/   日々の開発、調査、レビュー、リリースの運用手順
research/    試行・調査から得た知見。一次情報へのリンクを残す
decisions/   長く効く意思決定の記録（ADR）
docs/        このリポジトリ全体を案内する文書
```

## 方針

- ルールは、実際の失敗や反復判断を減らすものだけを残す。
- `AGENTS.md` は恒久的な制約、Skills は作業工程、プロジェクト固有の事情は各プロジェクトに置く。
- まず動く最小構成を作り、必要になったときだけ手順や自動化を増やす。
- 事実・仕様・外部ツールの記録には、確認日と一次情報を添える。
